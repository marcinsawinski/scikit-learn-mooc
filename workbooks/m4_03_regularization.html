📒 Workbook M4.03 — Keeping the weights under control#

In the lab we saw that a linear model with many features can overfit, and that regularisation (Ridge and its alpha, the C of the logistic regression) holds its weights back. In this workbook you regularise the traffic model, in a situation where it badly needs it: little data and hundreds of useless columns. You will watch the weights shrink as alpha grows, compare two kinds of penalty, and see two things that go wrong without regularisation or without scaling.

How this workbook works

  • The code is written for you. You do not need to write code, but you need to understand every step.

  • Every ____ is a gap. Fill it in with the value asked for in the text above the cell. The error NameError: name '____' is not defined means: a gap is still empty.

  • check(...) tells you whether your value is right (✅) or stops with a hint (❌).

  • commit(...) records a prediction before you see the result. Be honest: a wrong prediction costs nothing, it is how you learn.

  • Questions marked 🧠 Think are not checked here. You will need the answers for the Moodle quiz and for the discussion at the start of the next lab.

1. One month of data and 300 useless columns#

A new traffic sensor has been running for one month (January 2016). We must build a model from that month and it will be judged on the seven months that follow.

We describe each hour with the features that worked in workbook M4.02 (one column per hour of the day, the workday, and their interactions), plus four weather measurements: 53 real columns.

And there is a complication. A colleague, “to be on the safe side”, has attached 300 more columns taken from sensors that have nothing to do with the road. We simulate them with random numbers and call them junk_000 to junk_299. Nothing in them can help.

import matplotlib.pyplot as plt
import numpy as np
import pandas as pd

traffic = pd.read_csv(
    "https://raw.githubusercontent.com/marcinsawinski/scikit-learn-mooc/refs/heads/main/datasets/metro_traffic.csv",
    parse_dates=["date_time"],
)
traffic = traffic[traffic["rain_1h"] < 100].reset_index(drop=True)  # the impossible reading of M4.01
traffic["hour"] = traffic["date_time"].dt.hour
traffic["temp_c"] = traffic["temp"] - 273.15
traffic["workday"] = (
    (traffic["date_time"].dt.day_of_week < 5) & (traffic["holiday"] == "No holiday")
).astype(int)


def describe(rows, n_junk=300):
    """The 53 real columns, followed by `n_junk` columns of random numbers."""
    columns = {}
    for hour in range(24):
        columns[f"hour_{hour:02d}"] = (rows["hour"] == hour).astype(float)
        columns[f"hour_{hour:02d}_on_workday"] = ((rows["hour"] == hour) & (rows["workday"] == 1)).astype(float)
    columns["workday"] = rows["workday"].astype(float)
    for name in ["temp_c", "clouds_all", "rain_1h", "snow_1h"]:
        columns[name] = rows[name]
    junk = np.random.default_rng(0).normal(size=(len(rows), n_junk))
    for i in range(n_junk):
        columns[f"junk_{i:03d}"] = junk[:, i]
    return pd.DataFrame(columns, index=rows.index)


data = describe(traffic)
target = traffic["traffic_volume"]
real_columns = [name for name in data.columns if not name.startswith("junk")]
junk_columns = [name for name in data.columns if name.startswith("junk")]

is_train = traffic["date_time"] < "2016-02-01"
is_test = (traffic["date_time"] >= "2016-02-01") & (traffic["date_time"] < "2016-09-01")
data_train, target_train = data[is_train], target[is_train]
data_test, target_test = data[is_test], target[is_test]
print(f"{len(real_columns)} real columns + {len(junk_columns)} junk columns = {data.shape[1]} columns")
print(f"{len(data_train)} hours to learn from, {len(data_test)} hours to test on")

3. Ridge: paying for large weights#

Ridge is the same linear model with one extra rule: large weights cost something. While learning, it balances two goals: fit the training data, and keep the weights small. alpha sets the price of the weights: with alpha near 0 it behaves like the ordinary linear regression, and the larger alpha, the smaller the weights.

from sklearn.linear_model import Ridge

alphas = np.logspace(-1, 5, 13)
rows, ridge_weights = [], []
for alpha in alphas:
    ridge = make_pipeline(StandardScaler(), Ridge(alpha=alpha)).fit(data_train, target_train)
    ridge_weights.append(ridge[-1].coef_)
    rows.append(
        {
            "alpha": alpha,
            "training error": mean_absolute_error(target_train, ridge.predict(data_train)),
            "testing error": mean_absolute_error(target_test, ridge.predict(data_test)),
        }
    )
ridge_curve = pd.DataFrame(rows).set_index("alpha")
ridge_weights = pd.DataFrame(ridge_weights, index=alphas, columns=data.columns)

ax = ridge_curve.plot(logx=True, marker="o", figsize=(7, 3.5))
_ = ax.set(xlabel="alpha (log scale)", ylabel="mean absolute error", title="Validation curve of Ridge")

This is a validation curve, as in module 2, and this time it has the textbook U shape.

5. ➕ Going further: two thermometers#

Back to the full two years of data and a different danger. The table has the temperature in degrees Celsius. Suppose a second sensor reports the same temperature in Fahrenheit, rounded to the degree. The two columns say almost exactly the same thing: they are collinear.

We train a model on these two columns alone, five times, each time leaving out a different fifth of the data, and look at the two weights.

from sklearn.model_selection import KFold, cross_validate

two_thermometers = pd.DataFrame(
    {"temp_c": traffic["temp_c"], "temp_f": (traffic["temp_c"] * 9 / 5 + 32).round(0)}
)
folds = KFold(n_splits=5, shuffle=True, random_state=0)


def weights_per_fold(model):
    fitted = cross_validate(model, two_thermometers, target, cv=folds, return_estimator=True)["estimator"]
    return pd.DataFrame(
        [estimator[-1].coef_ for estimator in fitted],
        columns=["weight of temp_c", "weight of temp_f"],
        index=pd.RangeIndex(1, 6, name="fold"),
    )


ordinary_weights = weights_per_fold(make_pipeline(StandardScaler(), LinearRegression()))
ridge_weights_folds = weights_per_fold(make_pipeline(StandardScaler(), Ridge(alpha=100)))
pd.concat({"linear regression": ordinary_weights, "Ridge": ridge_weights_folds}, axis=1).round(0)

Both columns measure the temperature, and we know from workbook M4.01 that warmer hours have a little more traffic. Read the weights of the ordinary linear regression fold by fold: in some folds temp_c gets a large positive weight and temp_f a negative one, in others the reverse.

✏️ With which model do the weights keep the same sign and about the same size in every fold? Write "linear regression" or "Ridge".

stable_weights = ____
check("stable_weights", stable_weights)

When two columns carry the same information, only their combined effect is fixed by the data. The linear regression is free to give +1000 to one and −900 to the other, or the opposite, and tiny changes in the data decide which. The predictions are fine; the weights mean nothing. Ridge prefers small weights, so it splits the effect between the two columns, the same way every time.

6. ➕ Going further: the penalty depends on the units#

Ridge makes large weights expensive. But the size of a weight depends on the unit of its feature. Cloud cover is stored in percent (0 to 100). Stored as a fraction (0 to 1), the same model needs a weight 100 times larger.

in_percent = traffic[["temp_c", "clouds_all", "hour"]]

candidates = {

    predictions_fraction = model.fit(in_fraction, target).predict(in_fraction)
    change[name] = np.abs(predictions_percent - predictions_fraction).max()
pd.Series(change, name="largest change in a prediction (vehicles per hour)").round(1).to_frame()

A model whose predictions depend on whether somebody wrote 0.4 or 40% is not acceptable. This is the third reason to scale before a linear model (after convergence in module 1 and comparable weights in workbook M4.01): regularisation only treats the features fairly when they are on the same scale.

7. The same idea for classification: C#

LogisticRegression is regularised too, by default. Its dial is called C and it works in the opposite direction from alpha: C is the freedom given to the weights, not their price.

We predict heavy traffic (more than 4500 vehicles) from the January data with all 353 columns, for several values of C.

from sklearn.linear_model import LogisticRegression

heavy_train, heavy_test = target_train > 4500, target_test > 4500
rows = []
for C in [0.0001, 0.01, 1, 100]:
    classifier = make_pipeline(StandardScaler(), LogisticRegression(C=C, max_iter=5000))
    classifier.fit(data_train, heavy_train)
    rows.append(
        {
            "C": C,
            "size of the weights": np.linalg.norm(classifier[-1].coef_),
            "training accuracy": classifier.score(data_train, heavy_train),
            "testing accuracy": classifier.score(data_test, heavy_test),
        }
    )
by_C = pd.DataFrame(rows).set_index("C")
by_C.round(3)
