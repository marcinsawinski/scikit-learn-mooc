📒 Workbook M1.03 — Using categorical features#

In the lab we encoded the categorical columns of the adult census with OrdinalEncoder and OneHotEncoder, and combined them with the numerical columns in a ColumnTransformer. In this workbook you do the same on the 1985 wages survey, and you will meet categories the model has never seen, a trap in how the data is ordered, and a question of fairness.

How this workbook works

  • The code is written for you. You do not need to write code, but you need to understand every step.

  • Every ____ is a gap. Fill it in with the value asked for in the text above the cell. The error NameError: name '____' is not defined means: a gap is still empty.

  • check(...) tells you whether your value is right (✅) or stops with a hint (❌).

  • commit(...) records a prediction before you see the result. Be honest: a wrong prediction costs nothing, it is how you learn.

  • Questions marked 🧠 Think are not checked here. You will need the answers for the Moodle quiz and for the discussion at the start of the next lab.

import hashlib
import warnings

warnings.filterwarnings("ignore", category=FutureWarning)

ANSWERS = {
    "all_features_accuracy": "342a441fd887344f",
    "n_binary_columns": "4b227777d4dd1fc6",
    "n_categorical": "7902699be42c8a8e",
    "n_columns_if_binary": "b17ef6d19c7a5b1e",
    "n_onehot_columns": "f5ca38f748a1d6ea",
    "n_ones_unknown": "5feceb66ffc86f38",
    "worst_fold": "ef2d127de37b942b"
}

def _normalize(value):
    if isinstance(value, float) and value.is_integer():
        value = int(value)
    if isinstance(value, float):
        value = round(value, 2)
    if isinstance(value, (list, tuple, set)):
        return ",".join(sorted(str(v).strip().lower() for v in value))
    return str(value).strip().lower()


def _hash(value):
    return hashlib.sha256(_normalize(value).encode()).hexdigest()[:16]


def check(name, value):
    """Stop with a hint unless `value` is the expected answer for `name`."""
    if _hash(value) != ANSWERS[name]:
        raise ValueError(
            f"❌ {name} = {value!r} is not right. "
            "Re-read the text above this cell and try again."
        )
    print(f"✅ {name}")


def check_score(name, value, actual):
    """Stop with a hint unless `value` is `actual` rounded to 2 decimals.

    For results that differ slightly between computers (e.g. k-NN ties).
    """
    if not isinstance(value, (int, float)) or abs(value - round(actual, 2)) > 0.005:
        raise ValueError(
            f"❌ {name} = {value!r} is not right. "
            "Read the score printed above and round it to 2 decimals."
        )
    print(f"✅ {name}")


def commit(prediction, options):
    """Record a prediction before seeing the result."""
    if prediction not in options:
        raise ValueError(f"Choose one of {options} first.")
    print(f"📌 Your prediction: {prediction!r}. Now run the next cell and compare.")

1. Data and target#

As before, each row is a person surveyed in 1985 and we predict whether they earn more than $10 an hour. This time we use all the other columns.

make_column_selector picks columns by their type. Columns that are not numbers hold labels: they are our categorical columns.

4. ➕ Going further: a category the model has never seen#

The encoder learns the list of categories during fit. What happens when, later, a new person has an occupation that was not in the training data?

new_person = pd.DataFrame({"OCCUPATION": ["Student"]})

encoder = OneHotEncoder(sparse_output=False)
encoder.fit(data[["OCCUPATION"]])
try:
    encoder.transform(new_person)
except ValueError as error:
    print("ValueError:", error)

By default the encoder refuses: it raises an error. In production, this would crash the whole prediction service for one unusual person.

The option handle_unknown controls this. ✏️ Set it to the value that makes the encoder ignore unknown categories (as a string; see the error message above or the documentation).

handle_unknown = ____
encoder = OneHotEncoder(handle_unknown=handle_unknown, sparse_output=False)
encoder.fit(data[["OCCUPATION"]])
pd.DataFrame(encoder.transform(new_person), columns=encoder.get_feature_names_out())

✏️ How many 1s are in the encoded row of our student?

n_ones_unknown = ____
check("n_ones_unknown", n_ones_unknown)

5. A full pipeline#

make_column_transformer applies a different preprocessing to each group of columns: one-hot encoding for categorical columns, scaling for numerical ones. Then a logistic regression makes the prediction.

from sklearn.compose import make_column_transformer
from sklearn.linear_model import LogisticRegression
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler

preprocessor = make_column_transformer(
    (OneHotEncoder(handle_unknown="ignore"), categorical_selector),
    (StandardScaler(), numerical_selector),
)
model = make_pipeline(preprocessor, LogisticRegression(max_iter=1000))
model

➕ Going further: does the order of the rows matter?#

Let us cross-validate this model with 5 folds, exactly as in the lab:

from sklearn.model_selection import cross_validate

scores = cross_validate(model, data, target, cv=5)["test_score"]
scores.round(2)

✏️ One fold is much worse than the others. Which one? Give its number, counting from 1 to 5.

worst_fold = ____
check("worst_fold", worst_fold)

With cv=5, scikit-learn cuts the data in order: the first fold tests on the first fifth of the rows, the last fold on the last fifth. Let us look at the share of high wages along the file:

fifth = pd.Series(range(len(target))) * 5 // len(target) + 1
target.groupby(fifth).mean().round(2).rename_axis("fifth of the file")

The rows are not in random order: the share of high wages changes a lot from one part of the file to another. The last fold is trained on the first four fifths (roughly a quarter of high wages) and tested on the last fifth, where more than half of the people earn more than $10. It is tested on people who are quite different from the ones it was trained on.

The fix: shuffle the rows before cutting them into folds. StratifiedKFold(shuffle=True) does that, while keeping the same share of each class in every fold.

🔮 Predict first. With shuffling, will the fold scores be “more spread out”, “about as spread out” or “less spread out”?

my_prediction = ____
commit(my_prediction, ["more spread out", "about as spread out", "less spread out"])

from sklearn.model_selection import StratifiedKFold

cv = StratifiedKFold(n_splits=5, shuffle=True, random_state=0)
scores = cross_validate(model, data, target, cv=cv)["test_score"]
print(scores.round(2), f"mean {scores.mean():.2f} ± {scores.std():.2f}")

We use this shuffled cv for all the comparisons below.

7. ➕ Going further: ordinal instead of one-hot#

OrdinalEncoder replaces each category by a single number (0, 1, 2…) in alphabetical order. For OCCUPATION that gives:

from sklearn.preprocessing import OrdinalEncoder

ordinal = OrdinalEncoder().fit(data[["OCCUPATION"]])
dict(zip(ordinal.categories_[0], range(len(ordinal.categories_[0]))))

🧠 Think. For a linear model, Service (5) now counts “five times more” than Management (1). Does that order mean anything?

🔮 Predict first. Will the ordinal version of the pipeline score “much lower”, “about the same” or “much higher” than the one-hot version?

my_prediction = ____
commit(my_prediction, ["much lower", "about the same", "much higher"])

ordinal_model = make_pipeline(
    make_column_transformer(
        (OrdinalEncoder(handle_unknown="use_encoded_value", unknown_value=-1), categorical_selector),
        (StandardScaler(), numerical_selector),
    ),
    LogisticRegression(max_iter=1000),
)
ordinal_scores = cross_validate(ordinal_model, data, target, cv=cv)["test_score"]
print(f"one-hot : {scores.mean():.2f} ± {scores.std():.2f}")
print(f"ordinal : {ordinal_scores.mean():.2f} ± {ordinal_scores.std():.2f}")

The difference is small here. ✏️ One reason: for a column with only two categories, ordinal encoding (0/1) and one-hot encoding carry exactly the same information. How many of our 7 categorical columns are binary?
